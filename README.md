# Система управления персоналом

Веб-приложение для кадрового учёта, обработки заявок сотрудников и ведения табеля рабочего времени. Разработано в рамках дипломной работы.

Цель проекта — объединить основные кадровые процессы в одной системе: предоставить сотрудникам личный кабинет, специалистам отдела кадров — инструменты для работы с персоналом, а администратору — управление справочниками и аналитику.

Интерфейс приложения выполнен на русском языке. Доступ к разделам определяется ролью пользователя.

## Возможности

### Личный кабинет

- Просмотр сведений о сотруднике, его отделе, должности и стаже работы.
- Отображение остатка дней отпуска и статистики посещаемости за текущий месяц.
- Просмотр последних заявок и персональных уведомлений.
- Редактирование контактных данных и смена пароля.
- Формирование справки с места работы в формате PDF.

### Заявки сотрудников

- Подача заявок на отпуск, больничный и командировку.
- Указание периода, причины и прикрепление подтверждающего документа.
- Указание места и цели командировки.
- Просмотр собственных заявок и их статусов.
- Рассмотрение заявок отделом кадров: одобрение или отклонение с комментарием.
- Сохранение автора и даты принятого решения.
- Уведомление сотрудника о результате рассмотрения.

### Кадровый учёт

- Добавление и редактирование карточек сотрудников.
- Назначение отдела, должности и роли в системе.
- Хранение контактных данных, даты приёма и годовой нормы отпуска.
- Поиск, фильтрация, сортировка и постраничный просмотр списка сотрудников.
- Архивирование учётных записей с сохранением связанной истории.

### Табель рабочего времени

- Просмотр отметок сотрудников за выбранный месяц.
- Фильтрация по сотруднику, отделу и должности.
- Внесение отметок явки, неявки, отпуска и больничного.
- Добавление комментариев к отметкам.
- Отражение одобренных заявок в табеле.

### Уведомления

- Создание информационных, важных и предупреждающих сообщений.
- Рассылка всем пользователям либо выбранным сотрудникам, ролям и отделам.
- Настройка периода отображения уведомления.
- Просмотр сообщений и отметка об их прочтении.

### Справочники и аналитика

- Управление справочниками отделов и должностей.
- Просмотр численности сотрудников и распределения по отделам и должностям.
- Анализ заявок по типам и статусам.
- Графики динамики заявок за последние 12 месяцев.
- Статистика посещаемости за текущий месяц.

## Роли пользователей

| Возможность | Сотрудник | HR-специалист | Администратор |
| --- | --- | --- | --- |
| Личный кабинет, профиль и PDF-справка | Да | Да | Да |
| Подача и просмотр собственных заявок | Да | Да | Да |
| Просмотр табеля | Свой отдел | Все отделы | Все отделы |
| Редактирование табеля | Нет | Да | Да |
| Кадровый учёт | Нет | Да | Да |
| Рассмотрение заявок | Нет | Да | Да |
| Управление уведомлениями | Нет | Да | Да |
| Управление отделами и должностями | Нет | Нет | Да |
| Аналитика | Нет | Нет | Да |

HR-специалист не может рассматривать собственные заявки и управлять учётными записями администраторов. Сотрудник без назначенного отдела видит в табеле только свои отметки.

## Сценарий работы с заявкой

1. Сотрудник выбирает тип заявки, указывает даты и заполняет необходимые сведения.
2. Система сохраняет заявку со статусом «Новая» и проверяет пересечение с существующими заявками сотрудника.
3. HR-специалист или администратор рассматривает заявку и принимает решение.
4. При одобрении заявки в табеле появляются соответствующие отметки. Командировка учитывается как явка.
5. Сотрудник получает уведомление и видит результат в личном кабинете.

В проекте используется модель отпускного баланса по календарному году. Норма задаётся отдельно для каждого сотрудника и по умолчанию составляет 28 дней. Учитываются календарные дни одобренных отпусков; перенос остатка между годами и исключение праздничных дней не предусмотрены.

## Технологии

| Компонент | Технология |
| --- | --- |
| Серверная часть | PHP 8.2+, Laravel 12 |
| База данных | MySQL 8 |
| Доступ к данным | Eloquent ORM, миграции Laravel |
| Интерфейс | Blade, HTML, CSS, JavaScript |
| Графики | Chart.js 4.5.1 |
| PDF-документы | Laravel Dompdf |
| Автоматические тесты | PHPUnit 11, SQLite |
| Управление зависимостями | Composer, npm |

Приложение построено по архитектуре MVC. Правила рассмотрения заявок и расчёт отпускного баланса выделены в сервисы `LeaveWorkflow` и `VacationBalance`. Графики загружаются из локальных ресурсов проекта.

## Локальный запуск

### Требования

- PHP 8.2 или новее и Composer 2.
- MySQL 8.
- Расширения PHP: PDO MySQL, mbstring, fileinfo, curl, DOM и XML; GD для обработки изображений в PDF.
- PDO SQLite для запуска автоматических тестов.
- Node.js и npm — для пересборки ресурсов Chart.js. Для обычного запуска приложения они не требуются: готовые ресурсы находятся в репозитории.

### 1. Установка зависимостей

Клонируйте репозиторий или скачайте его архив, перейдите в корневую папку проекта и выполните:

```bash
composer install
```

### 2. Настройка окружения

Скопируйте шаблон настроек:

```bash
cp .env.example .env
```

В Windows PowerShell используйте:

```powershell
Copy-Item .env.example .env
```

Создайте базу данных MySQL, например:

```sql
CREATE DATABASE diplom CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

Укажите в `.env` параметры своего подключения:

```dotenv
APP_NAME="Система управления персоналом"
APP_ENV=local
APP_URL=http://127.0.0.1:8000

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=diplom
DB_USERNAME=your_mysql_user
DB_PASSWORD=your_mysql_password
```

Значения `your_mysql_user` и `your_mysql_password` замените на имя и пароль своего пользователя MySQL.

### 3. Подготовка приложения

```bash
php artisan key:generate
php artisan migrate
```

Для заполнения новой локальной базы демонстрационными данными выполните:

```bash
php artisan db:seed
```

Seeder создаёт отделы, должности, администратора, трёх HR-специалистов, двадцать сотрудников и примеры уведомлений. Заполнение предназначено для новой демонстрационной базы и доступно в окружениях `local` и `testing`.

### 4. Запуск сервера

```bash
php artisan serve --host=127.0.0.1 --port=8000
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000) в браузере.

### Демонстрационные аккаунты

После выполнения `php artisan db:seed` доступны следующие учётные записи:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Администратор | `admin` | `admin123` |
| HR-специалист | `ivanova` | `hr12345` |
| HR-специалист | `petrov` | `hr12345` |
| HR-специалист | `smirnova` | `hr12345` |

Для демонстрационных сотрудников используется пароль `employee123`. Их логины можно посмотреть в разделе «Кадровый учёт», войдя под администратором или HR-специалистом.

Эти аккаунты предназначены для локальной демонстрации дипломного проекта. Для установки без демонстрационных данных администратора можно создать командой:

```bash
php artisan personnel:create-admin admin
```

Команда запросит пароль интерактивно.

## Ресурсы интерфейса

Шаблоны расположены в `resources/views`, стили — в `public/css`, JavaScript — в `public/js`. Для обновления локальной сборки Chart.js выполните:

```bash
npm ci --ignore-scripts
npm run build
```

Скрипт копирует библиотеку, карту исходного кода и лицензию в `public/vendor/chart.js`.

## Тестирование

Для запуска тестов:

```bash
php vendor/phpunit/phpunit/phpunit
```

Если PDO SQLite установлен, но не включён в конфигурации PHP, его можно подключить при запуске:

```bash
php -d extension=pdo_sqlite vendor/phpunit/phpunit/phpunit
```

Тесты используют отдельную базу SQLite в памяти. Они проверяют права доступа, кадровые операции, обработку заявок, отпускной баланс, согласованность табеля, доступ к документам, уведомления и авторизацию.

Дополнительные проверки:

```bash
composer validate --strict
node --check public/js/app.js
```

## Структура проекта

```text
app/
├── Console/Commands/     # Команды управления приложением
├── Http/Controllers/     # Обработка запросов
├── Http/Middleware/      # Контроль доступа
├── Models/               # Модели данных
└── Services/             # Правила заявок и отпускного баланса
database/
├── migrations/           # Структура базы данных
└── seeders/              # Демонстрационные данные
public/
├── css/                  # Стили интерфейса
├── js/                   # Клиентские сценарии
└── vendor/chart.js/      # Локальная библиотека графиков
resources/views/          # Шаблоны Blade
routes/                   # Маршруты приложения
scripts/                  # Сборка ресурсов
storage/app/private/      # Приватные вложения к заявкам
tests/                    # Автоматические тесты
```

Основные сущности: сотрудник, отдел, должность, заявка, отметка табеля и уведомление. Сотрудники связаны с отделами и должностями; заявки и отметки табеля принадлежат сотрудникам. Факт прочтения уведомления хранится отдельно для каждого получателя.

Вложения к заявкам доступны через авторизованный маршрут. Для размещения приложения корневой каталог веб-сервера должен указывать на `public/`, а файл `.env` и содержимое `storage/` не должны публиковаться в репозитории.
